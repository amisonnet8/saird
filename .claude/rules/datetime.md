# 日時の扱い

**データでは UTC で持ち、人に見せるときだけ、その人のタイムゾーンに直す。**

Rust の標準ライブラリにあるのは`std::time::SystemTime`（瞬間）と`Duration`だけで、暦（年月日）・書式・タイムゾーンは無い。日時を書式にする・タイムゾーンに直すコードを書くときは、日時の crate が要る。**どの crate を足すかは、人間に聞く判断**（`.claude/rules/working-with-human.md` 1章。依存を足すため）。下の決まりは、どの crate でも同じ。

## 持つとき（保存・受け渡し）

- ファイル・DB・JSON・ログ・API・設定・テープなど、**人の画面の外に出る日時は、すべて UTC**。形式は RFC 3339 の `Z` つき（`2026-10-14T01:32:00Z`。必要ならミリ秒まで `…:00.123Z`）
- UTC の瞬間を RFC 3339 の書式で書く。ローカル時刻で書いたものや、`+09:00` などのオフセットつきを**新しく書かない**
- **読むときは、`Z` もオフセットつきも両方読める**ようにする（RFC 3339 として読めば両方読める）。古いデータは書き換えない
- ファイル名・ID に日時を入れるなら、それも UTC
- 内部では瞬間の型（`SystemTime`、または crate の瞬間の型）で扱う。文字列のまま持ち回らない

## 見せるとき（表示）

- 人に見せる境目（画面・CLI の出力・メール・人が読むログ）で、**利用者のタイムゾーンに直す**（`TZ` 環境変数・OS の設定に従う）
- タイムゾーン名を固定（`"JST"`・`Asia/Tokyo`）で埋め込まない。利用者の設定に従う。固定が要る仕様（営業日・締め時刻など）は、そのタイムゾーンを**名前（IANA）で設定に持ち**、コードに書かない
- 画面にタイムゾーンの違いが紛れるときは、オフセットや名前を添える

## 比べる・計算する

- 時刻は**瞬間で比べる**（瞬間の型の比較演算子。`SystemTime`も`<`・`==`で比べられる）。**文字列で比べない**（`Z` と `+09:00` は、同じ瞬間でも文字列が違う）
- 日付だけのもの（誕生日・締め日）は瞬間ではない。タイムゾーンに依存しない**日付として**別に持つ（`2026-10-14`）。UTC の午前0時にして持たない（見る場所で前日・翌日になる）
- 「今」は関数で差し替えられるようにする（「今」を返す関数やトレイトを引数で受ける。`SystemTime::now()`をあちこちで直接呼ばない）。**テストは本物の現在時刻に頼らない**

## テスト

- 固定した日時で確かめる。タイムゾーンに関わる変更は、`TZ=UTC` と `TZ=Asia/Tokyo` の両方で流す（手元は JST、CI は UTC のことが多い。文字列比較のテストは、手元でだけ通る）
- 表示が利用者のタイムゾーンに従うことは、タイムゾーンを引数で渡すテストで確かめる（テストの中で`TZ`を書き換えない。`.claude/rules/testing.md`「テストの中で環境変数を変えない」）
