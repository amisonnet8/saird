.claude/	リポジトリで共有する Claude Code の設定
	hooks/	Claude Code が道具の前後に動かすフック
		build.sh	srwr で .rs・Cargo.toml・Cargo.lock を変えたあとに qsoku build を動かす
		crube-untracked.sh	srwr の new でファイルを作ったあと、説明の無いパスを言語ごとに Claude に知らせる
		require-bcuz.sh	bcuz を通さない Bash のコマンドを断る PreToolUse フック
		require-bcuz.test.sh	require-bcuz.sh が通す・断るコマンドの表（qsoku hook）
	rules/	このリポジトリで作業するときのルール（日本語）。いつ読むかは CLAUDE.md にある
		bcuz-usage.md	Bash のコマンドを bcuz で動かす方法と、秘密をコマンドに書かないこと
		crube-usage.md	crube の使い方：MCP と CLI、場所の探し方、両方の言語の説明の保ち方
		datetime.md	日時の扱い：UTC で持ち、表示だけ利用者のタイムゾーンに直す
		directory-structure.md	ファイルの置き場所、リポジトリの構成、信頼の層ごとのコードの分け方
		distribution.md	配布の方法：コマンドを GitHub Releases で配る、実装の版と仕様の版、goreleaser と cargo-zigbuild、リリースの流れ
		documentation.md	文書の書き方：言語、文体、docs/ の直し方、例の値は道具で求める、経緯は mtqg に書く
		mtqg-usage.md	mtqg でメモ・todo・質問・不具合・決まり事を記録する方法
		naming.md	命名規則（決まったら書く）
		qsoku-usage.md	ビルド・テスト・lint の qsoku の名前と呼び方
		srwr-usage.md	ファイルは srwr だけで変える（厳格モード）こと、テープの閉じ方
		testing.md	テスト方針と、サンドボックス・OS ごとの CI の落とし穴
		working-with-human.md	人間への頼み方：小さなつまずき、確認、見え方の了承
	settings.json	Claude Code の許可・サンドボックス・フック（人間が管理する）
	skills/	Claude Code のスキル
		commit-with-tape/	スキル：srwr のテープを閉じてコミットする
			SKILL.md	スキルの手順
		mutation-check/	スキル：実装をわざと壊して、テストが気づくか確かめる
			SKILL.md	スキルの手順（構文の変異は cargo mutants、spec.txt は mutants -spec）
			spec.txt	プロジェクトの仕様の約束を1つずつ壊す変異の一覧（仕様の言葉で書く。最初は空）
			mutants/	spec.txt の変異を入れてテストを回す道具（独立した Go モジュール）
				go.mod	モジュールの定義（このプロジェクトとは別）
				main.go	一覧の変異（と Go のファイルの構文の変異）を1つずつ入れ、ファイルを元に戻す
				main_test.go	道具のテスト

qsokufile	ビルド・テスト・lint の名前つきコマンド（qsoku）
.goreleaser.yaml	配布物の作り方（goreleaser）
	| タグで .github/workflows/release.yml が、手元では qsoku snapshot が使う。コマンド saird（src/main.rs）を作る。コマンドが出す版は Cargo.toml の版。.claude/rules/distribution.md を参照。
Cargo.lock	依存の版の固定（cargo が書く。コミットする）
Cargo.toml	workspace の定義：crate の一覧、共通の版・Rust の版・lint の水準、crate 同士の依存
about.hbs	配布物に入れるライセンス文のひな形（cargo-about）
about.toml	cargo-about の設定：許すライセンスと、配布物のターゲット
deny.toml	cargo-deny の設定：脆弱性・許すライセンス・禁止する crate・出どころ
rust-toolchain.toml	このリポジトリの Rust のツールチェイン（stable。rustfmt・clippy つき）
crates/	workspace の Rust の crate。信頼基盤の層ごとに1つ
	saird-core/	小さく監査する層：構文解析、型と制約、式の評価器、kv の範囲と包含、検査器、封印のハッシュ、レシートなどの形式と検証器
		Cargo.toml	saird-core のパッケージ。ほかの crate に依存せず、依存は最小にする
		src/	saird-core のソース
			lib.rs	saird-core のライブラリの入口。最初のモジュールまではプレースホルダー
			syntax/	契約を構文木にする（docs/reference/syntax.md）。ここでは文法だけを確かめる
				mod.rs	syntax の入口：parse_contract、構文木、位置、エラー
				ast.rs	契約の構文木（位置つき）
				error.rs	ソースの中の位置と、行・列つきの構文の誤り
				lexer.rs	字下げ、続きの行、ブロック、字句
				parser.rs	契約と式のパーサとそのテスト（docs の ReserveStock の例を含む）
	saird-runtime/	広く使われる層：ホスト、標準箱（kv・clock）、テスト実行器、レシートの発行
		Cargo.toml	saird-runtime のパッケージ。saird-core にだけ依存する
		src/	saird-runtime のソース
			lib.rs	saird-runtime のライブラリの入口。最初のモジュールまではプレースホルダー
	saird/	コマンド saird と、人間に見せる表示（権限サマリ、対応表）
		Cargo.toml	コマンド saird のパッケージ。saird-core と saird-runtime に依存する
		src/	コマンド saird のソース
			lib.rs	saird（表示）のライブラリの入口。コマンドを足すまではプレースホルダー
