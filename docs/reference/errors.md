# 失敗とエラー

呼び出しの結果は、`ok`、`error`(契約で宣言したもの)、`fault` のいずれかである。

| fault | 判定基準 | 責任 |
|---|---|---|
| `resource` | 燃料切れ、メモリ上限、タイムアウト | 実行環境 |
| `host` | 相手のプロセスの停止、通信の失敗、標準箱の障害 | 実行環境 |
| `violation.input` | 入口で入力が `in` の制約を満たさない | 呼んだ側 |
| `violation.trap` | Wasm の trap(実装のバグによる停止) | 呼ばれた側 |
| `violation.output` | 出口で、出力が型や制約を満たさない | 呼ばれた側 |
| `violation.error` | 宣言していないエラー、または `when` が成り立たない状況でのエラー | 呼ばれた側 |
| `violation.permission` | 範囲外の操作を試みた | 呼ばれた側 |
| `violation.ensures` | 抽出検査で `ensures` が成り立たなかった | 呼ばれた側 |

- 呼ぶ側は、`error` を全種類処理しなければならない(検査器が確認する)。`fault` は、処理するか、親へ伝える。何もしなければ親へ伝える。
- `atomic` な箱の `fault` は、kv への書き込みが取り消された状態で返る。
- `violation` はすべてレシートに記録する。呼ばれた側の責任となる `violation` が起きた封印物は、警告の対象にする。
- 例外やスタックトレースは、箱の外に出さない。
- `ensures` の抽出検査(本番の一部の呼び出しで `ensures` を確かめる)は、実行時設定で有効にできる。
- 診断には、レシート、リプレイ、失敗入力の最小化(shrinking)を使う。
