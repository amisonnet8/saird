# 生成テスト

| 規則 | 内容 |
|---|---|
| 入力の生成 | `in` の型と制約から生成器を導出する。上限のない値は検査器が拒否する。長さと数値は範囲内で一様に選び、全体の10%は境界値(最小・最大)にする |
| 状態の生成 | `state kv covers X` は、X の各要素に対応するキーを必ず作ることを意味する。値は値型の制約から生成する。ほかに無関係なキーを0〜5個加える。`state` を書かない場合、kv は値型の制約からランダムに作る |
| 判定 | `ok` なら `ensures` をすべて検査する。`error` なら、`when` が最初に成り立つエラーと一致するかを検査する |
| 最低成立件数 | `ok` と各エラーについて、`min_hits` 件以上起きなければならない。足りない結果には、例テストが1つ以上必要である。どちらもなければ不合格 |
| 件数の既定値 | `runs 1000`、`min_hits 50` |
| seed | 封印物が確定した後に、テスト実行器が決める(封印物のハッシュと透明性ログの記録から導出する) |

例テストの値は代表値として扱う。[ReserveStock](../examples/reserve-stock.md) では、`covers` によって `UnknownSku` は生成テストでは起きない。そのため例テストで確かめている。
