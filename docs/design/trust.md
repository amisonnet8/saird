# 封じ込めと証拠

## 保証の分担

| 段階 | 保証すること | 担い手 |
|---|---|---|
| 静的検査 | 封印物の import ⊆ `needs` の標準箱。各箱に渡す権限 ⊆ 親の権限。effects の宣言条件 | 検査器 |
| 実行時の強制 | 範囲外の操作を止める(範囲を限定した capability だけを渡す)。入口・出口の検査 | ホスト・標準箱 |
| 記録 | 権限の使用を記録し、署名付きのレシートにする | ホスト |

ホストと標準箱には、範囲外の操作を止めることを確かめる適合テストを、版ごとに行う。

権限の範囲の書き方は [権限](../reference/permissions.md) を参照。

## 信頼基盤

| 層 | 構成 | 信頼の根拠 |
|---|---|---|
| 小さく監査する層 | 検査器、レシート検証器 | 小さく保ち、公開して監査する |
| 広く使われる層 | ランタイム(Wasmtime など)、ホスト、標準箱、テスト実行器 | 再現可能ビルド、ハッシュによる照合、適合テスト |
| 鍵 | 信頼基盤の署名鍵、承認者の鍵 | 鍵の管理と失効 |

保証は、OS とハードウェアを信頼することを前提とする。

## レシート

レシートが示すのは、**「指定した信頼基盤が、指定した封印物と契約に対して、記録された条件でテストを実行し、この結果を得たこと」**である。

レシートには、次の内容を記録する。

- 封印物・契約・依存部品・信頼基盤のハッシュ
- seed、件数、例テストと生成テストの合否
- 観測プロファイル
  - 結果の分布(例:OK 612 / OutOfStock 388)
  - 権限の操作の種類ごとの回数
  - 燃料とメモリの最大値と中央値
- 作り直した回数と、落ちたテスト

テストのレシートには入出力をすべて含める。本番のレシートでは入出力をハッシュ化する。透明性ログ(追記だけができる公開ログ。Sigstore の Rekor など)には、ハッシュだけを載せる。

## テストの妥当性

1. **対応表**:`ensures` の各項目と各エラーについて、成立件数と例テストを表示する。不足している項目は赤く表示する。
2. **ミューテーションテスト**:検出力を参考値として表示する。
3. **AIの分離**:実装を書くAIと、テストを書くAIを分ける。例テストの一部はホールドアウトとして別ファイルに置く。ホールドアウトも人間の承認対象だが、実装AIには渡さない。

人間はテストを追加できる。人間が書いたテストには印を付ける。

## 承認

本番に出せるのは、**契約承認**と**適合証明**の両方がそろった封印物だけである。

**実装だけが変わった場合**は、次の条件をすべて満たせば、人間の再承認なしで新しい適合証明を出す。

1. 新しい seed で、全テスト(ホールドアウトを含む)に通る。
2. 同じ seed で生成した入力を旧版と新版に与えたとき、出力と kv の変化がすべて一致する。
3. 旧版にない種類の権限操作がない。
4. 燃料とメモリの最大値が、旧版の1.5倍以内である。

いずれかを満たさない場合は、人間の再承認が必要である。このとき、観測プロファイルの差分を表示する。

**契約が変わった場合**は、再承認が必要である。差分を表示する。

- 互換な変更(入力制約の緩和、`ensures` の追加、エラーの削除)では、呼び出し元はそのままでよい。
- 非互換な変更(上記以外のすべて)では、呼び出し元の適合証明も取り直す。
