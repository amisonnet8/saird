# 弱点・未解決の問題

1. テストは有限である。`ensures` に書いていない振る舞いは保証されない。
2. 実装は、テスト環境かどうかを見分けて振る舞いを変えうる。seed の事後決定、差分テスト、観測プロファイル、抽出検査で緩和するが、防ぎきれない。
3. 契約そのものの誤りは検出できない。
4. 品質の要求(「良いおすすめ」など)は、`ensures` に書きにくい。
5. 権限の範囲内での情報の持ち出しや、サイドチャネルは防げない。秘密情報の伏せ字は、加工された形の漏えいまでは防げない。
6. 信頼基盤のバグは、全体のバグになる。特にランタイムは大きい。
7. 箱が増えると、承認が形だけになりやすい。
8. 生成器の偏りは、最低成立件数でしか検出できない。
9. 補償の正しさは、親の箱の契約とテストに依存する。
10. 境界でのコピーと検査のため、細かい箱を多く呼ぶ処理は遅い。
11. 内部を見ないため、障害の切り分けが難しい。
12. 「契約と証拠を信頼する」ことが、組織や監査に受け入れられるかが課題である。
